# MVP Scope

## Must have

- authentication and pseudonymous public profile;
- catalogue of buildings/complexes;
- address/name/map search;
- property creation and duplicate handling;
- structured reviews;
- review versions;
- unverified and verified experience signals;
- safe evidence upload and retention workflow;
- moderation, reports, appeals, right of reply;
- admin interface;
- Georgian-ready multilingual model;
- basic analytics and audit log;
- privacy/export/deletion request handling.

## Should have

- helpful votes with anti-abuse limits;
- property photo gallery;
- representative claim workflow;
- review update reminders after time;
- notification email for moderation results;
- compare two or three properties;
- basic map clustering.

## Could have after validation

- neighbourhood reviews;
- issue timelines («лифт не работал → исправлено»);
- subscriptions to a property;
- invitations from existing residents;
- automated text translation with original always available;
- public aggregate statistics by district;
- reputation for contributors.

## Explicitly out of MVP

- full property listings marketplace;
- payments and promoted listings;
- agent CRM;
- mortgage products;
- transaction closing;
- legal due-diligence guarantee;
- public ratings of individual landlords/tenants;
- chat between users;
- AI deciding whether allegations are true;
- complex gamification.

## Scope gate

A requested feature enters MVP only if it is required for one of these loops:

1. Find property → understand experience.
2. Submit experience → publish safely.
3. Verify relationship → improve trust signal.
4. Report/dispute → resolve safely.
5. Moderate/administer → operate without database access.

Everything else goes to roadmap unless it removes a launch blocker.
