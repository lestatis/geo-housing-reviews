# Geo Housing Reviews

> Рабочее техническое название. Бренд и публичное название выбираются отдельно.

Платформа для отзывов о домах, жилых комплексах и опыте проживания в Грузии. Пользователь сможет найти объект, увидеть структурированные отзывы, отличить подтверждённый опыт проживания от неподтверждённого и принять более осознанное решение об аренде или покупке.

В будущем поверх каталога и отзывов может быть добавлен модуль объявлений о продаже и аренде жилья.

## Основная ценность

Существующие площадки показывают цену, площадь и фотографии, но почти не отвечают на вопросы:

- насколько шумно в доме и районе;
- как работают лифты, отопление, вода и управляющая компания;
- есть ли плесень, перебои, проблемы со стройкой или документами;
- насколько честно ведут себя собственники, агенты и застройщики;
- совпадает ли рекламное описание с реальным опытом жильцов.

Платформа должна собирать этот опыт в структурированном, проверяемом и безопасном виде.

## MVP

1. Каталог домов и ЖК.
2. Поиск по адресу, названию, району и карте.
3. Карточка объекта с агрегированной оценкой и тематическими рейтингами.
4. Создание структурированного отзыва.
5. Фотографии к отзыву с удалением метаданных.
6. Жалобы, модерация и право на ответ.
7. Несколько уровней подтверждения опыта проживания.
8. Приоритет подтверждённых отзывов без скрытия остальных.
9. Минимальная административная панель.

Полный объём MVP: [`docs/PRD_MVP.md`](docs/PRD_MVP.md).

## Предлагаемая техническая основа

- **Backend:** Java, Spring Boot, модульный монолит.
- **Database:** PostgreSQL + PostGIS.
- **Mobile:** React Native + Expo.
- **Admin:** Next.js.
- **Contracts:** OpenAPI как контракт между backend и клиентами.
- **Media:** S3-совместимое объектное хранилище.
- **Search:** сначала PostgreSQL; отдельный поисковый движок только после измеренной необходимости.

Архитектура не считается окончательно утверждённой до принятия ADR, но документация и границы модулей уже подготовлены под этот вариант.

## Как начать

1. Прочитать [`docs/DOCUMENTATION_INDEX.md`](docs/DOCUMENTATION_INDEX.md).
2. Согласовать открытые продуктовые решения из [`docs/DECISION_LOG.md`](docs/DECISION_LOG.md).
3. Создать первый ADR по финальному стеку аутентификации.
4. Создать GitHub Project и перенести задачи из [`docs/ROADMAP.md`](docs/ROADMAP.md).
5. Запустить первую задачу Claude Code или Codex по шаблону из [`docs/AI_WORKFLOW.md`](docs/AI_WORKFLOW.md).
6. Перед первым PR выполнить:

```bash
./scripts/check.sh
```

## AI-инструменты

- `AGENTS.md` — общий контракт для Claude Code, Codex и других агентов.
- `CLAUDE.md` — импортирует `AGENTS.md` и добавляет правила Claude Code.
- `.claude/rules/` — точечные правила, часть из них загружается только для нужных путей.
- `.claude/skills/` и `.agents/skills/` — повторяемые рабочие процессы.
- `.claude/agents/` — специализированные read-only субагенты для анализа и ревью.
- `.claude/hooks/` — детерминированные ограничения, включая запрет обходить `sudo` и системные разрешения.
- `docs/plans/` и `docs/handoffs/` — переносимое состояние нетривиальных задач; передача между агентами проверяется по Git и тестам.
- `prompts/INDEPENDENT_REVIEW.md` — независимое read-only ревью в новой сессии перед решением человека о merge.
